# 重做单文件 HTML 应用的 UI

## 什么时候用

- 用户要「2.0」「重做一版」「优化一下」「太丑了」「要小而美」
- 对象是单个 `.html`，CSS 与 JS 全内联的那种工作台 / 面板

**这套流程的价值：模型只碰外观，数据和逻辑一个字节都不经过它**——所以再怎么改都不可能改坏功能。

## 铁律（踩过坑的）

1. **源文件只读**。全程不写源文件，只写新目录。
2. **不覆盖已生成的旧版**，先归档再写新的（用户可能要对比）。
3. **不删除**。废弃件一律 mv 到 `_废弃_<日期>\`（回收站 API 调不通，Add-Type 被拦）。
4. **用户说「简洁/美」= 减法 + 审美，两者都要给**，只给一个必然翻车（已翻两次）。
5. **禁止类指令要写「克制」而不是「禁止」**：写「允许一层极淡阴影」好过「禁止阴影」——
   后者会逼模型只敢压字号压间距，交出「压缩版原版」。
6. **必须单独点名保留静态资源**（二维码 / 内联 SVG 图标 / 图标字体），模型一律当装饰删掉。
7. **永远不要让模型写云端存储接口**，把正确的 SDK 写法原样抄进 prompt 让它沿用。

## 流程

### 1. 摸家底
```python
# 看总字符、script 块、最大的几行
```
重点找出**数据常量**（常常一行十几万字符）。它们占大头却跟设计无关，必须抽走。

### 2. 拆出「外壳」与「JS」
```python
m = re.search(r"<script[^>]*>[\s\S]*?</script>", src)
shell = src[:m.start()] + "<!--APP_SCRIPT-->\n" + src[m.end():]   # 给模型看
JS_ORIG = src[m.start():m.end()]                                   # 自己留着拼回
```

### 3. 抽静态锚点（id / class）
`id` 是 JS 找容器的钩子，一个都不能少；`class` 必须在 CSS 里有选择器，否则 JS 动态生成的
内容会变成没样式的裸文字。
**注意过滤 JS 模板拼接的伪名**（形如 `' + r.id + '`、`'+(it.late?`），只留合法 CSS 标识符。

### 4. 写投喂包
结构：先写【任务】→【前提：JS 已抽走，只做骨架+CSS】→【硬约束】→【你要决定的部分】→【输出要求】→ 源码。

硬约束清单模板：
- 原样保留 `<!--APP_SCRIPT-->`
- 所有 N 个 id 必须存在（**允许隐藏、不允许删除**）
- 所有 M 个 class 必须有样式（可改外观不可改名）
- 体积上限：**CSS ≤ X 字符、骨架 ≤ Y 字符**（一定要量化）
- 单文件、零外部依赖、纯 ES5、手机竖屏可用

「小而美」的配方（写进 prompt，别省）：
- 正文 14–15px，**不要 11–12px**
- 卡片间距 12–16px，行高 1.5–1.6
- `:hover` / `:active` / `:focus` 必带，配 0.15–0.2s 过渡
- 允许**一层**极淡阴影做层次
- 配色要有个性（别用 Bootstrap 默认蓝 `#2563eb`）
- 补线性 SVG 图标（stroke 1.5–1.75，16–20px）

### 5. 选模型（实测结论）
| 场景 | 模型 |
|---|---|
| 短问答 / 工具调用 | `deepseek-v4-flash`（最快最稳） |
| **生成几万字符的长文件** | **`kimi-k3`（唯一扛得住的）** |

glm-5.2 和 deepseek-v4-flash 在 3 万字符输出任务上都会**读超时**（实测 50 分钟 / 41 分钟失败）。
kimi-k3 会 429，**用退避 20/40/60/90/120/150 秒、最多 8 次的重试器挂后台跑**，别指望即时返回。
**max_tokens 是耗时主杠杆**：30,000 → 26,000 后从 37 分钟降到 2.5 分钟。

### 6. 还原 + 五道闸口
把 `<!--APP_SCRIPT-->` 替换回原 JS，然后逐项校验：
1. 占位符恰好 1 个
2. id 覆盖 100%
3. class 样式覆盖（缺的要在原版里本来也缺才算数）
4. 外部依赖 = 0
5. `node --check` 抽出 JS
任一不过就**不要写成品**。

### 7. 补静态资源
模型大概率删掉二维码 SVG 和图标。用 `patch_qr.py` 那类小脚本从原版取回注入容器。

### 8. 冒烟 + 审美体检
- 冒烟：无头 DOM stub + 云端 SDK 桩，跑一遍 JS，看执行是否报错、DOM 是否被填充。
  **先跑原版拿基线**，新版与基线一致才算 PASS。
- 审美体检：`audit_beauty.py`，11 项打分。≥9 可交付，7 合格，<7 退回重做。
  用户说「丑」时先跑它，能定位到具体是哪一项（字号/间距/hover/配色/图标）。
